# OctoAcme Project Management Processes

## Overview

OctoAcme follows a structured, customer-first approach to project management that emphasizes iterative delivery, clear ownership, data-informed decisions, and psychological safety. This documentation hub provides guidance for all team members on how we plan, execute, and improve our projects.

### Core Principles
- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments
- **Clear ownership**: Each project has a named Project Manager and Product Lead
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback and learning

## Project Lifecycle

OctoAcme projects follow five key stages:

1. **Initiation** – Validate business need, align stakeholders, and define success criteria. This stage produces a lightweight one-pager capturing the problem statement, goals, success metrics, risks, and resource needs.

2. **Planning** – Break work into shippable increments, identify dependencies and risks, and create a prioritized backlog with clear acceptance criteria and a Definition of Done.

3. **Execution** – Build, test, review, and iterate on deliverables using daily standups, small pull requests, automated CI checks, and continuous quality validation.

4. **Release** – Deploy to production following standardized checklists, run smoke tests, verify post-deployment, and communicate changes to stakeholders and support teams.

5. **Close & Retrospective** – Capture learnings and identify actionable improvements through structured retrospectives that convert insights into concrete action items.

## Core Roles

- **Project Manager (PM)**: Coordinates delivery, manages schedules, risks, and communications to keep projects on track
- **Product Manager (PdM)**: Defines outcomes, prioritizes the backlog, and measures success through key metrics
- **Developers**: Implement features, collaborate on design and testing, and help identify technical risks
- **QA/Testing**: Validate quality, confirm acceptance criteria are met, and perform manual testing when needed
- **Stakeholders**: Provide inputs, approvals, and strategic guidance

## Communication and Quality

OctoAcme maintains a consistent communication rhythm through daily standups, weekly delivery syncs, and monthly stakeholder updates. Risk and dependency tracking is central to the process, with escalation paths that move from team-level triage to the PM, Product Lead, and Sponsor when needed.

Quality is built into every stage: acceptance criteria are defined during planning, small PRs with linked issues are required during execution, automated testing and security scanning run in CI before review, and smoke tests verify critical flows before release. Retrospectives after each sprint or milestone ensure continuous improvement through documented action items.

## Quick Start for New Team Members

1. Read the [Project Management Overview](octoacme-project-management-overview.md) for a high-level introduction to the OctoAcme approach.
2. Review your role in [Roles and Personas](octoacme-roles-and-personas.md) to understand responsibilities and communication patterns.
3. Follow the relevant lifecycle stage documents as you work on projects: Initiation → Planning → Execution → Release → Retrospective.
4. Use the [Risk Management & Communication](octoacme-risks-and-communication.md) guide for escalations, status updates, and stakeholder coordination.
